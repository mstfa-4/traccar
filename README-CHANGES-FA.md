# راهنمای تغییرات — Traccar ۲۳۱۳

این بسته شامل سه قابلیت درخواستی است که روی سورس سرور (traccar) و سورس وب‌کلاینت (traccar-web) پیاده‌سازی، بیلد و به‌صورت عملی تست شده است.

---

## ۱) مسدودسازی پس از ۵ تلاش ناموفق ورود + محافظت در برابر DDoS

### رفتار جدید (پیش‌فرض)
- پس از **۵ تلاش ناموفق** ورود (رمز اشتباه):
  - **حساب کاربری** در دیتابیس مسدود می‌شود (ستون `blocked` در جدول `tc_users`) و مسدودی تا زمان بازگشایی توسط مدیر باقی می‌ماند.
  - **آدرس IP** مهاجم به مدت **۱۵ دقیقه** مسدود می‌شود و پس از آن به‌صورت خودکار رفع می‌شود.
- **محدودسازی نرخ (ضد DDoS):** حداکثر **۳۰ درخواست ورود در دقیقه** از هر IP؛ درخواست‌های بیشتر با کد `429` و پیام «تعداد درخواست‌ها بیش از حد مجاز است» رد می‌شوند.
- پس از ورود موفق، شمارنده تلاش‌های ناموفق حساب و IP صفر می‌شود.
- **حساب‌های مدیر (administrator) هرگز به‌صورت خودکار مسدود نمی‌شوند** تا آخرین مدیر قفل نشود؛ در عوض فقط IP متخاصم مسدود می‌شود.
- مسدودی حساب حتی برای ورود با توکن (API) نیز اعمال می‌شود.
- آدرس واقعی کلاینت از هدرهای `CF-Connecting-IP`، `X-Real-IP` و `X-Forwarded-For` (در صورت وجود) تشخیص داده می‌شود؛ در غیر این صورت از `remoteAddr`.

### تنظیمات اختیاری در traccar.xml
```xml
<entry key='login.maxAttempts'>5</entry>       <!-- حداکثر تلاش ناموفق (پیش‌فرض ۵) -->
<entry key='login.ipBlockMinutes'>15</entry>   <!-- مدت مسدودی IP به دقیقه (پیش‌فرض ۱۵) -->
<entry key='login.rateLimit'>30</entry>        <!-- حداکثر درخواست ورود در دقیقه از هر IP (پیش‌فرض ۳۰) -->
```

### بازگشایی توسط مدیر
- در **تنظیمات → کاربران** (`/settings/users`) جلوی هر حساب مسدود یک **آیکن قفل قرمز** نمایش داده می‌شود.
- کاربر **admin** با کلیک روی آیکن «قفل باز» در ستون عملیات همان ردیف، حساب را مسدودگشایی می‌کند (درخواست `POST /api/users/unblock/{id}`).
- همچنین در صفحه ویرایش کاربر، چک‌باکس «مسدود» فقط برای admin فعال است و با ذخیره، وضعیت انسداد تغییر می‌کند.
- فقط مدیر می‌تواند وضعیت «مسدود» را تغییر دهد؛ در ویرایش‌های دیگر کاربران، مقدار قبلی حفظ می‌شود (تا یک مدیرِ غیرِ admin نتواند حساب را باز کند یا کارشناسان به‌اشتباه انسداد را بردارند).

## ۲) تاریخ شمسی با ورود دستی و ماسک خودکار در همه فرم‌ها

کامپوننت جدید `src/common/components/JalaliDateTimeField.jsx` (به‌همراه `src/common/util/jalaali.js` برای تبدیل تقویم، بدون وابستگی جدید npm):

- **ورود دستی عددی:** کاربر فقط ارقام را تایپ می‌کند و ماسک به‌صورت خودکار `/` و `:` و فاصله را در جای درست می‌گذارد — نمونه: تایپ `140409021430` نمایش داده می‌شود `1404/09/02 14:30`.
- **ارقام فارسی و عربی** (۰-۹ / ٠-٩) نیز پذیرفته و نرمال می‌شوند.
- **اعتبارسنجی:** ماه/روز نامعتبر (مثل ماه ۱۳ یا روز ۳۱ دی) خطای «تاریخ واردشده معتبر نیست» می‌دهد؛ حذف جداکننده‌ها هم درست کار می‌کند (با Backspace یک رقم حذف می‌شود).
- **تقویم شمسی:** با دکمه تقویم، پاپ‌آور ماه‌جاری شمسی باز می‌شود (سرستون‌ها ش ی د س چ پ ج، ناوبری ماه/سال، هایلایت امروز و مقدار انتخابی، دکمه «امروز» و برای تاریخ‌زمان دکمه «همین حالا» و فیلد ساعت ماسک‌دار).
- **سازگاری کامل با بک‌اند:** مقدار ذخیره‌شده همچنان ISO/UTC است؛ فقط نمایش و ورودی شمسی شده است.
- تبدیل تقویم در بازه ۱۹۷۰ تا ۲۰۵۰ میلادی با تقویم رسمی (Intl Persian) مقایسه و تأیید شد (۲۷٬۲۱۶ تاریخ، بدون خطا).

## نحوه بیلد و استقرار

### وب‌کلاینت
```bash
cd traccar-web
npm install
npm run build        # خروجی در پوشه build/
# محتوای پوشه build را در پوشه web سرور قرار دهید (مثلاً /opt/traccar/web)
```
> خروجی بیلد‌شده جدید در همین بسته داخل `traccar-web/build` قرار دارد و می‌توانید بدون بیلد مجدد مستقیماً مستقر کنید.

### سرور
```bash
cd traccar-server
./gradlew jar copyDependencies
# خروجی: target/tracker-server.jar و وابستگی‌ها در target/lib
```
در اولین اجرا، ستون `blocked` به‌صورت خودکار توسط Liquibase به دیتابیس اضافه می‌شود.

## سایر اصلاحات انجام‌شده در بسته

چند مورد ناقص در زیپ‌های دریافتی برای رسیدن به بیلد سالم اصلاح شد:
- بازگرداندن پوشه `src/resources` (ترجمه‌ها و تصاویر) که در `traccar-web-2313.zip` جا افتاده بود (از کپی داخل بسته سرور).
- بازسازی پوشه `public/` (آیکن‌ها، فونت وزیرمتن، styles.css و logo) از خروجی بیلد موجود.
- نرمال‌سازی انتهای خطوط CRLF به LF در `gradlew` تا اجرای بیلد سرور ممکن شود.

## خلاصه تست‌های انجام‌شده
- بیلد کامل سرور با Gradle (JDK 21) موفق؛ فایل‌های تغییریافته بدون خطای Checkstyle.
- بیلد کامل وب با Vite و ESLint موفق.
- تست عملی سرور اجراشده: ۵ تلاش ناموفق از ۵ IP مختلف → مسدودی حساب و پاسخ `403 errorAccountBlocked`؛ ۵ تلاش از یک IP → مسدودی IP و پاسخ `403 errorIpBlocked`؛ بیش از ۳۰ درخواست در دقیقه → `429 errorTooManyAttempts`؛ بازگشایی توسط admin از طریق API و رابط کاربری → ورود مجدد موفق؛ حساب admin هرگز خودکار مسدود نشد.
- تست مرورگر واقعی: نمایش پیام فارسی مسدودی در صفحه ورود، آیکن قفل و دکمه بازگشایی در صفحه کاربران، ماسک تاریخ با ارقام لاتین و فارسی، و انتخاب تاریخ از تقویم شمسی.
